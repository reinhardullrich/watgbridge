# History import

History support is opt-in. It requests available history from the phone and stores
text, captions, sender identifiers, original timestamps and private attachment
download references in the bridge database. Treat this database as sensitive.
It does not automatically copy historical messages into Telegram.

```yaml
history_sync:
  enabled: true
  days_limit: 90
```

The days limit is a request, not a guarantee. Initial history settings are used at
pairing. For an existing session, receive a new message in a selected chat to create
an anchor, then request older messages. Do not delete session databases or unlink
devices merely to test this feature. A fresh pairing may be needed for initial bulk
history, but is not required by the on-demand request API.

Only the configured owner, in the owner's bot DM or configured Telegram group, can
run these commands. Additional sudo users cannot access them.
Chats in `whatsapp.ignore_chats` are excluded from caching and history commands.

- `/history`: list up to 20 cached chats, counts and oldest dates.
- `/history fetch JID`: request up to 50 messages before the oldest cached message
  in that exact chat. Keep the phone online. Requests are limited to one per minute.
  A successful request does not prove the phone returned messages. Check `/history`.
  Repeat only while the oldest date/count progresses; there is no automatic loop.
- `/history import JID COUNT`: copy up to 200 unimported cached messages, oldest
  first, into that chat's Telegram topic. Start with a small count such as 5.
- `/history import-message JID MESSAGE_ID`: import exactly one cached message,
  for targeted imports without copying everything preceding it.
- `/history refresh JID`: re-fetch up to 50 messages before the newest cached
  message, enriching existing text-only records with attachment references.
  This does not post anything to Telegram. It shares the one-minute fetch limit.
- `/history attachments JID COUNT`: fill in attachments for existing history
  imports only, without importing additional messages. Download failures can be
  retried with this command; uncertain Telegram deliveries require manual review.

The JID is the exact identifier shown by `/history` (for example
`123456789@s.whatsapp.net`). Imports are new Telegram messages with the original
date/sender in their body; Telegram posting dates cannot be backdated. Importing
an older batch later therefore appends it to the topic. Long text is attached as a
complete UTF-8 text document rather than truncated.

Photos, videos, audio, documents and stickers are downloaded on import. Existing
short placeholders become media messages with the same Telegram message ID.
Long text stays intact and the file is added as a reply in the same topic.
Photos over 10 MiB or configured as files, and stickers, are sent as documents.
Files over 49 MiB are refused explicitly. Temporary media is streamed to private
disk-backed storage and removed after each attempt; set TMPDIR to a private
directory. Download references include media keys and are never safe to publish.
Unsupported non-text types, view-once and disappearing messages are excluded.
Old media may no longer be downloadable. Failure leaves the placeholder intact
and reports an error; it does not mark the attachment complete.

For a text-only installation, refresh the selected chat first, then use
`attachments`. Only messages returned by the phone can acquire missing references;
refresh is a bounded recent batch, not a complete lifetime re-fetch.

History never runs through the live WhatsApp handlers: no command execution,
read receipts, reactions or messages to WhatsApp contacts are generated by import.
Fetching history sends only a protocol request to the owner's primary device.

Imports skip messages already mapped to Telegram. A persistent delivery reservation
prevents automatic retries if a network failure or crash leaves delivery uncertain.
Such a `pending` delivery needs manual reconciliation against the Telegram topic;
do not blindly delete its reservation and retry. Multiple bridge processes using
one database are unsupported. Chat ID aliases are not automatically merged.
Pending imports are counted by `/history`. Each import command has a five-minute
deadline, including cancellable Telegram rate-limit waits.
Message and attachment delivery are recorded separately. A confirmed text message
is never reposted merely because its attachment failed. An uncertain media edit or
send is reserved as pending and not automatically repeated, even after restart.

Tests use temporary databases and a fake Telegram client, not live accounts.
Live phone-history and Telegram delivery testing is required before declaring the
installation verified. Keep history/config/session databases private and excluded
from Git. For upstream review, the startup-order fix is a separate commit.
